目标：让浏览器版 IDE 内置中文支持，并在中文系统上默认使用中文，不引入 git 子模块。

## 1. 预置上游中文语言包（applications/browser）

- 在 `applications/browser/package.json` 的 `dependencies` 中新增：
  `"vscode-language-pack-zh-hans": "open-vsx:MS-CEINTL.vscode-language-pack-zh-hans"`
- 配置插件输出目录：设置 `theiaPluginsDir`（参考 `examples/browser/package.json` 的 `"theiaPluginsDir": "../../plugins"` 模式），使构建时 `@theia/application-manager` 把该扩展自动下载展开到 plugins 目录，随产物打包（离线可用）。
- 确认启动脚本 `--plugins=local-dir:...` 指向的目录与上述一致。
- 版本通过 yarn lockfile 锁定；语言包更新只需改版本号。

## 2. 中文系统默认使用中文（theia/packages/core）

- 修改 `packages/core/src/browser/preload/i18n-preload-contribution.ts`：
  - 当 `localStorage['localeId']` 不存在（用户从未显式选择语言）时，读取 `navigator.language`（Electron 端天然等于系统语言），若以 `zh` 开头则把 locale 设为 `zh-cn`，否则回落到 `defaultLocale`。
  - 注意现有逻辑会把"不完整的语言包"重置回 `defaultLocale`：预置语言包后 zh-cn 是完整的，此保护不受影响；顺序上保证语言包注册发生在前端 preload 之前（现状即如此，语言包由后端启动时注册）。
- 兜底配置：在 `applications/browser/package.json` 的 `theia.frontend.config` 中设置 `"defaultLocale": "zh-cn"`（产品级默认，即使检测逻辑失效也默认中文）。
- 用户通过 "Configure Display Language" 显式选择过语言的，仍以 localStorage 为准，不被覆盖。

## 3. 自建翻译文件承载新增功能字符串（与上游包合并）

- 在本仓库为自定义功能维护翻译，走 Theia 核心 i18n 模式：在相关 package 内提供 zh-cn 翻译 JSON，框架 `LocalizationProvider.loadLocalization()` 会将其与上游语言包合并（同 key 后注册者覆盖）。
- 新增代码中的用户可见字符串一律使用 `nls.localize()`，未翻译时安全回退英文。
- 起步阶段可以只搭机制、翻译内容逐步补充。

## 验证

- `yarn` 安装 + 构建 browser 应用，确认 plugins 目录中出现 `vscode-language-pack-zh-hans`。
- 中文系统/浏览器语言下首次启动：界面默认中文；清掉 localStorage 在英文环境下启动：默认英文。
- 切换语言 quick-pick 仍正常工作。
- 修改系统语言后重装/清缓存场景抽查一次。
